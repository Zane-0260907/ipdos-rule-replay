# Frozen pilot contract: evidence-scoped approvals

This is an isolated capability prototype. The delivered conservative application, 420-trial study and submitted papers are not modified. No target score is asserted. Dependency tracking, guarded commits, selective invalidation and transaction repair are existing techniques; the intended system value is an executable bounded contract, inspectable impact explanation and safe field-scoped re-review in an actual application.

## Approval identity and protected view

An approval is append-only and records actor, workflow/draft/clause identity, contract/engine version, rule versions, original full evidence snapshot ID, approved decision outputs, protected evidence tokens and their digest. It never points to a replacement snapshot. A retained approval keeps its original snapshot; a new validation attestation identifies the current revision and proves that the protected witness is unchanged. Changed display data are not silently attached to that approval.

Protected procurement evidence per SKU: proposed integer grams, forecast integer grams, on-hand integer grams, all matching active reserve rows (member key, generation, integer grams, reason key), joined reason active state, active inventory rule/buffer/max quantity, unit price, shared budget/committed-budget-use membership, all draft quantities/prices used by that shared condition, and the actor's view/review/commit grant versions. Zero proposed quantity does not remove inventory or rule evidence. Any protected fact/version or member identity change requires re-review even when suggested or total quantity stays numerically equal.

Display-only fields: ingredient/document titles, notes and descriptive labels not read by any protected decision. These fields are visibly distinguished from protected inputs in the review preview. The original evidence snapshot retains their reviewed historical values; current display values are shown separately.

Protected fields have monotonic field versions; delete/reinsert has a different generation. Predicate certificates include ordered member IDs/generations, protected field versions, normalized predicate and a monotonic membership-change epoch. Thus insert/delete, empty-to-nonempty, excluded-to-included, same-valued new members and changed-then-restored evidence are not mistaken for the original witness. Permission grant versions remain monotonic through revoke/restore.

Missing-key observations, including absent right-hand join keys, bind a persisted key-level absence epoch: the greatest committed event sequence for that exact table/key at observation time. Insert-then-delete therefore changes the absence token even if the key ends missing again. This and predicate membership epochs are reconstructed from the durable journal after normal restart, not kept only in process memory. A predicate epoch is scoped to its normalized predicate and table, and advances only on a before/after membership crossing; it is not the whole table revision. Exclude/include/exclude and deletion/reinsertion remain observable.

Identity/canonicalization is fixed: JSON types are distinct; numbers are safe integers (negative zero is canonical zero); null differs from an absent projected field through an explicit presence bit. Field sets and object keys are sorted by deterministic UTF-16 code-unit order; scan membership is ordered by unique row key. Strings are exact and case-sensitive with no Unicode folding. Key-token identities serialize the full table/key/field-set tuple rather than ambiguous concatenation or shortened digests. Rule/contract/engine version mismatch always forces re-review. Equality is evidence unchanged only within the declared DSL and trusted mediated-write/journal boundary, not an assertion about arbitrary outside database changes.

## Finite execution semantics

Supported: unique-key projected lookup (including missing-key observation); explicit AND/OR predicates with eq/ne/lt/lte/gt/gte/isNull/notNull; projected scans; many-left-to-one-unique-key joins; exact integer sum/count/distinct count (explicit null-skip only when declared); bounded nonempty text checks; key-set equality; finite comparisons, Boolean conjunction and bounded integer arithmetic. Read dependencies are captured by these operators, not an application-maintained affected-SKU list. Right-key changes can fan out to all joined left rows. Scan dependencies cover future matching insertions and old/new predicate membership, not only initially returned IDs. The distinct-count/text operators are used by the second document adapter and change the engine build; final procurement regression is required.

Filter comparisons with missing/null operands are unknown and retain a row only on true, except explicit null operators. Protected numeric aggregations reject missing, null, non-integer, negative-disallowed or overflow inputs; they never silently coerce to zero. Distinct row IDs are distinct members even when values coincide. Duplicate keys are rejected by the store. General many-to-many joins, arbitrary JavaScript, time and nondeterministic functions are unsupported. A declared legacy/opaque rule forces whole-contract global invalidation on every source revision; unknown code that cannot be evaluated safely is rejected.

Quantities are integer grams. Buffer is integer basis points: targetG = ceil(demandG * bufferBp / 10000). SuggestedG = max(0, targetG - max(0, onHandG - activeReserveG)). Money is integer cents; lineCostCents = ceil(proposedG * centsPerKg / 1000), summed exactly. Intermediate values must remain safe integers. Shared-budget evidence is shared by all affected line clauses; it is not represented as independent per-line authority.

## Atomic authority and re-review

Fact updates and complete before/after journal events share a transaction. Reviewed snapshots and approvals reject UPDATE/DELETE. A review preview seals what the user saw. Re-review compares current protected witnesses to that sealed preview in a transaction; stale preview evidence is refused. It appends approvals only for explicitly selected invalid/missing clauses. Unaffected approval IDs and original snapshots remain unchanged.

First commit uses BEGIN IMMEDIATE. Within that same transaction it authenticates the actor, checks current permission and rule state, reads the authoritative journal prefix/current witnesses, validates every required approval, verifies the current draft identity/content, writes the simulated receipt, updates any budget-use fact and writes the actor/key/request-hash result atomically. Analysis outside the transaction is only a cache/preview. A gap/reset in journal provenance forces full recomputation or conservative invalidation. Identical authorized-read retries retrieve the original persisted receipt before applying current write freshness; changed-body key reuse is rejected. Commit permission revocation never authorizes a new effect. No external action is executed.

This pilot requires the review actor and first-commit actor to be the same designated approver recorded in the immutable draft context. Other authorized readers may inspect data but cannot borrow that actor's approvals. Original reviewer grant/field versions remain in every protected witness, while the current caller's live commit permission is independently checked inside the transaction; revoke/restore cannot revive old approvals. Supporting different reviewer/committer actors is outside this slice.

There is at most one simulated receipt per draft, enforced both by an open/committed status check and a database UNIQUE(draft_id) constraint in the authority transaction. A different request key or actor cannot create another receipt for that draft. Retry mapping alone is not the duplicate guard. Cross-draft semantic/business-demand deduplication is not claimed.

The bounded prototype trusts its encapsulated fact-write interface and complete transactional journal. Raw out-of-band database mutation, schema tampering and arbitrary plugins are outside this mediation boundary and must not be described as protected without additional measures.

## Comparators and independent oracle

All comparators use the same approval contract: (1) whole revision binding; (2) key/row versions plus conservative table fences for scan/join phantoms; (3) full recomputation of all protected witnesses/rules; (4) dependency-based incremental evaluation. These are self-implemented local comparators, not executions of Guarded Commits, OCC or MV3C authors' systems. A pure observed-row-only comparator, if shown, is diagnostic and explicitly unsafe for phantoms; it is not ranked against safe modes only on speed.

The independent oracle uses separate complete materialization code and complete data scans/history. It does not reuse the incremental candidate selection, invalidation index or dirty-node logic. It checks every change's expected retained/review-required decisions and final commit outcome. Member identity and protected evidence are compared, not just final numbers. Zero false retention/incorrect new commits is a hard gate: any such error pauses expansion and invalidates safety claims until fixed and rerun; it cannot be averaged away.

## Prespecified pilot matrix and bounds

First end-to-end slice: approve rice/chicken/greens and shared budget; change inventory belonging to another store; retain the original approvals only in precise modes; commit once, repeat the same request and retrieve the same receipt. Then change the actual rice on-hand field: rice requires re-review even if manually proposed grams are unchanged; unrelated line approvals retain their original snapshot IDs. Re-review from an explicitly refreshed preview, then commit atomically.

The pilot covers: unchanged control; unrelated store/SKU update; display-only update; related stock change; zero-quantity SKU stock change; same-output protected evidence change; matching insert; nonmatching insert; delete; predicate boundary crossing; null; duplicate key and distinct equal-valued members; key-join fanout/missing-right insertion; shared budget and another line price/quantity; rule update/revoke; permission revoke/restore; opaque fallback; stale review preview; change after preview/before commit; identical retry after changed source; changed-body key; normal restart; atomic write failure. Fix scenario definitions before execution in the machine-readable matrix. First run one deterministic trace per scenario/mode; only after zero safety errors use at most five repetitions per case and bounded scale points (3, 30, 120 decision items).

Measure unsafe retention/commit first, unnecessary invalidation relative to the oracle, required re-review fields/actions (workload proxies, not human time), validation/capture/commit latency, tracked dependency count/bytes and affected-node fanout. Preserve all negative results. If incremental cost does not improve on full recomputation at tested sizes, report that directly and position the capability around explanation and safely scoped review rather than speed. If it is merely a renamed rowset, stop novelty claims and reassess. A second, different local document-release workflow is attempted only after the procurement safety slice passes, using the same interpreter/service interface and independent document oracle. No platform expansion, user collection, paid API, publication or production operation.
