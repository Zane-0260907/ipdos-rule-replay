# Second bounded adapter: local document release authorization

This contract is fixed before the document pilot. It uses the same interpreter, immutable snapshot/review ledger, four safe validation modes, live designated-actor checks, atomic commit and per-draft receipt uniqueness as procurement. Only a declarative decision graph, intent-table binding, live-rule key and local simulated-effect writer differ. No document is published, uploaded or sent to any person.

Each protected release clause binds document identity, exact content digest, classification, readiness and version; the requested publication intent; every currently approved signoff member and its editor/content-digest/decision/version; each joined editor's active/can-sign/grant version; distinct eligible signer count and required quorum; current rule and actor grant versions. A signoff is eligible only for that exact content digest. Two rows signed by the same editor count as one signer, while both rows remain protected evidence members. Changing content therefore cannot reuse signatures on earlier content.

All clauses also bind a shared local-channel audience: every enabled member key and principal/role, joined principal active/grant state, nonempty-reader predicate, channel version, and the complete selected publication-key set. Changing audience membership or a shared policy affects both document clauses. An unsupported many-to-many join or arbitrary function is still outside the finite grammar. The finite operators add bounded nonempty text validation and exact distinct count; null can be explicitly skipped by the declared distinct-count expression. These additions change the engine build identity and require procurement regression on the final source.

Document title/note and principal display name are display-only. Original full snapshots retain their historical values. New member insertion, predicate crossing, missing editor key ABA, deletion/reinsertion and revoke/restore remain protected through the same persisted version/membership/absence mechanisms. Protected null or invalid data fail closed. The final simulated effect is one `localReleases` fact plus the immutable receipt and request outcome in the same authority transaction. No purchase, external file write or real publication is executed.

The independent document oracle manually scans full facts/history and materializes the complete protected view. It imports neither the production graph nor the dependency selector/predicate evaluator. The document matrix is frozen in `DOCUMENT_MATRIX.json`; first one trace per scenario/mode, then three deterministic repetitions only if zero false retained approvals, false new commits and partial effects. It is a second synthetic integration check, not evidence from real editors or readers.
