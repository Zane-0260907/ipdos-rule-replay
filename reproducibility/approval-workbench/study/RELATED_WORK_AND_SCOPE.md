# Positioning and evidence boundaries

Approval/evidence binding, safe decision reuse, dependency validation, selective invalidation and transaction repair are established work. This prototype does not claim a new concurrency-control algorithm. Its candidate system contribution is a bounded executable review contract, visible evidence/impact chains, explicit selected re-review and atomic local integration of those mechanisms across two different workflows.

[Guarded Commits](https://arxiv.org/html/2610.00037v1), §§3–3.1, already binds resolution records to artifacts, policy and executed paths. It requires context/capability checks for reuse and a new derived authorization event; its evaluation is trace reconstruction. Our prototype is not that authors’ implementation and does not claim a capability absent from it merely because this UI uses different terminology. Our retention model keeps original approvals and records current validation links; explicit renewal appends an approval. These are different declared record semantics, not evidence of algorithmic novelty.

[Authority at Commit Time](https://arxiv.org/html/2609.31490v1), §§2–4 and §6.4, explicitly treats authoritative admission as a composition of existing concurrency and verification techniques. It covers affected/unaffected dependencies and canonical outcomes after lost acknowledgments. This local prototype makes no claim to invent those principles. Its own tests address only its finite interpreter and SQLite effect boundary; they are not a reproduction of that paper’s outbox, delegated authority or networked experiments.

The [MV3C authors’ reproducibility repository](https://github.com/epfldata/mv3c) identifies an existing transaction-repair implementation and experimental package. We did not install, port or benchmark it. The publisher pages for that paper and the classical Kung–Robinson OCC article returned HTTP 403 during this review, so no detailed comparative performance claim is drawn from those pages. The database lineage is acknowledged; the four measured modes are self-implemented comparators under one local approval contract.

The finite DSL declares relevant data, rather than proving that an arbitrary application has declared every important business fact. Protected-version equality is meaningful only with trusted graph definitions and mediated writes plus the complete durable journal. The interpreter build fingerprint covers its expression/value/predicate code and the serialized graph definition; it is not a general deployment-signing system for every surrounding file or arbitrary plugin.

There is one local SQLite authority boundary. The functional suite includes two real child processes contending for a draft, normal child-process restart/retry, and separately injected SQLite exceptions. These do not establish distributed correctness, sustained multi-writer throughput or power-loss recovery. No real procurement, real publication, participant study, human time saving, model improvement or financial benefit was measured.

The full-recompute comparator rebuilds every graph node and protected data view, using the same compiled plan and validated historical membership-epoch prefix. The independent oracle separately scans/replays complete history without the candidate dirty-index implementation. Timing therefore compares warm local validation implementations; it is not a cold-start database benchmark or a complexity proof.

Shared-budget evidence legitimately fans out to all lines, so a price change can require everyone to review. Current snapshot and per-clause coarse metadata duplicate shared structures. Serialized byte counts and runtime at 120 lines expose this cost. The prototype should be positioned around inspectable evidence and operational review scope, with bounded measured validation savings; not as a scalable general-purpose transaction engine.
